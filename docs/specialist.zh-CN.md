# 认识小白兔专员

[English](specialist.md) · [简体中文](specialist.zh-CN.md) · [首页](../README.zh-CN.md)

小白兔专员是应用的管理助手：**独立、固定的一段原生 Codex 对话**，有自己的角色和工作资料。它理解交代，先查相关现状，再调用所属模块已经支持的接口。

它是第 7 项职责，复用第 3 项的运行基础，由第 5 项展示。数据、设置和校验仍由各模块负责，不另建第二套设置库或不受限制的管理入口。

## 一个小的交代入口

在左上输入框打字、发送，不会把正在看的页面切走。点击“小白兔专员”标题，才打开固定历史、操作记录及需要处理的原生确认。默认回答简短；右侧指南提供已支持选项和说法示例。

打开受支持的对话时，应用可以给管理指令附上目标类型、工作区和准确编号，不附聊天正文。准备期间目标变化，就保留指令，不悄悄套到另一段聊天。

刷新或重连仍沿用同一原生线程。专员连接当前使用固定的模型／强度请求策略，与普通 AI 配置分开；自动切模和多管理执行者尚未实施。

## 可以怎样吩咐

| 示例 | 当前范围 |
| --- | --- |
| “把界面改成深色。” | 共用、按版本保存的应用设置 |
| “把回答显示为原始文字。” | 可读目录中的低频显示设置，不修改保存的正文 |
| “新建一份叫‘项目工作’的配置。” | 已有 AI 配置创建、编辑接口，也可从现有配置开始新建；目录候选和保存参数仍需原生核验 |
| “只改这段对话的下轮配置。” | Codex／Pi／Hermes 下轮保存配置；Claude 选模型、强度沿用原生；DSH 局部模型写入口仍留空 |
| “下一轮用项目记忆，保持只读。” | 五种原生通路的下轮只读记忆选择，不清除现有会话上文 |
| “找到‘项目讨论’，先不发送。” | 核对准确对话／历史与来源身份 |
| “把这份整理文档放进已有的‘工作’分组。” | 受支持根目录内的 Markdown／引用分组；已有文件换组保留名字和正文 |
| “核对并更新。” | 手动程序事实 → 无工具 AI 分析 → 保存报告，不是自动全电脑扫描或修复 |
| “交给已有 Codex 对话，再取回它的回答。” | 绑定原目标与原请求编号的有限原生交办 |

记忆配置参数、文档记忆编辑、连接检查、真实检索和保存是不同操作。配置已保存或连接健康，不证明已经读写记忆正文；检查也不需要读取私人记忆全文。

## 手动状态报告

需要新报告时，在专员指南旁点击**核对并更新**。它不是定时巡检，当前流程把三件事分开：

| 步骤 | 做什么 | 证据范围 |
| --- | --- | --- |
| 程序事实 | 读取保存的 AI 配置、原生模型目录、专员工具连接元数据，以及明确选中记忆的连接元数据 | 每项保留来源、观察／读取时间、身份和证据摘要；没有选择记忆就标为未纳入，读不到的仍是未核实。 |
| AI 分析 | 只把这四项冻结事实交给可用的无工具文字连接，得到结构化判断和简短解释 | 每项必须引用原证据编号和摘要，不能把未知升级为已核实，也不把未启用直接当故障。 |
| 保存报告 | 校验答复，有限地再观察一次元数据，把事实、判断、说明和分析来源保存在本机 | 依据已变则标记不再适用；依据未核实或变化时报告为部分更新，分析失败另标未完成。不改配置、不创建目标聊天、不执行工具、不召回私人记忆，也不发测试任务。 |

管理专员仍是**固定的原生 Codex 对话**。当前状态分析走应用**已有的 Claude 配置文字适配器**，不是另一个有工具管理权限的专员。这个一次性文字通路关闭工具和原生对话持久化，只接收给定元数据；它可以沿用该通路实际配置的提供商／模型，不证明底层一定是 Anthropic 或某个型号。报告区分请求型号和连接报告型号。连接不可用或分析失败时，程序事实仍保留，说明标为未完成，不自动换路或重试。分析可能调用该连接配置的在线服务；报告标签及生成说明目前仍主要使用中文。

刷新或重新打开面板，按原检查编号读取保存报告。轻量身份／版本比较可以把旧判断标为依据已变化；普通读取不会重做工具／记忆 RPC 检查，也不再次调用模型。浏览器恢复会保留待核实检查，不悄悄创建第二份；服务换代后的未完成检查标为待核实，不自动补发。报告是带来源和时间的观察，不是对账号、模型、工具或服务持续可用的保证。

## 一次修改怎样限定范围

1. 找准对象，读取当前支持值和版本。
2. 复用合适配置；只改单段聊天时，必要时建立专用配置。
3. 通过与界面共用的业务接口提交有限改动。
4. 核对结果；冲突时重读，未知时保留原请求，不换编号重发。

只改一段对话，不应修改其他对话共用的配置。下轮选择也不重写已经发送的请求与回执。

配置界面使用**从此配置开始新建配置**，不暗示复制原生会话。原来的**设为新对话默认**动作已不再显示，需要时在输入框选择相应保存配置；已有选择和记录保留。

部分低频设置没有单项图形开关，人仍可阅读目录，由专员或受支持的程序接口执行修改。紫色表达这条程序通路已经实现，不表示本次操作已经获准。[颜色与设置设计](design.zh-CN.md)

## 交办与当前限制

五种 Agent 已有原生目标输入／结果通路，完整的专员往返证据更窄：Codex 已有完整链路，Claude 的材料交接已补证输入与原编号结果读取。这不代表所有目标、工具、中断都已验证。Pi／Hermes 的准确结果仍受当前连接缓存限制。

Claude 可以在**本机操作账本**中保留有界最终回答正文：只接受成功、未截断、不属于子任务的顶层 SDK final Result，最多 128 KiB，并保存原请求身份和 SHA-256。匹配的存储结果可在连接持有者关闭或重建后读回，标为 `stored_sdk_result`，不冒充当前仍有活连接。旧回执没有正文、失败、子任务、超限／截断、损坏或身份不符，都不会补造一份成功回答；这不是无限持久化，也不恢复完整原生会话状态。

必须把完整最终回答关联到原请求。已接受、进度片段或最近一条回复不能替代完成结果。缺少所需的准确缓存或存储证据时应说明不可用，不猜、不改编号补发。

原生权限仍由人处理。交办通过不等于免审批、桌面应用接管或所有设备都能控制。

## 仍不属于它的能力

- 代替人做登录、个人授权与原生审批决定。
- 直接接管 Codex 桌面或 WorkBuddy 的进行中工作。
- 只有界面的应用代操作，以及待接入的 AI／混合接口。
- 跨电脑调度和远程唤醒。
- 自动全局切模，或另造独立设置／执行系统。

专员可以解释未接入区域，准备受支持的下一步；不能把安装过程序、看到了工具目录或完成了计划称为已经接通。
