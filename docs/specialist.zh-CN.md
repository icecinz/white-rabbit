# 认识小白兔专员

[English](specialist.md) · [简体中文](specialist.zh-CN.md) · [首页](../README.zh-CN.md)

小白兔专员帮你管理应用。你可以在**同一段专员对话里，选择 Codex 或 DSH 来执行**。每个核心各自保留原生会话、角色和已经收到的正文位置。专员先理解要求、查看现状，再使用负责该功能的模块所提供的接口。

本页介绍 **0.2.0-alpha.2 早期源码快照**。请先配好管理功能需要的环境和所选原生连接，继续使用原账号、提供商、工具和审批方式。

专员是第 7 项职责，使用第 3 项的运行基础，由第 5 项显示。各模块继续负责自己的数据、设置和检查，不另建第二套设置库，也不提供不受限制的管理入口。

## 一个小的交代入口

在左上输入框打字、发送，不会切走正在看的页面。点击“小白兔专员”标题，才打开固定历史、操作记录和需要处理的原生确认。回答默认简短，右侧指南列出支持的选项和说法示例。

打开支持的对话时，应用可以在管理指令中带上目标类型、工作区和准确编号，不带聊天正文。准备指令时目标变了，就保留指令，不悄悄改成操作另一段聊天。

刷新后仍保留同一段管理历史。Codex 和 DSH 各自保留原生身份、模型和提供商配置。在普通对话里选择 AI 配置，不会因此更换专员。所选核心仍使用自己的原生登录、工具和审批规则。

## 切换专员核心

在**设置 → 小白兔专员 → 专员核心**中，选择已接通的 Codex 或 DSH，不另外新建一张管理聊天卡片。原有 Codex 绑定和历史继续保留，角色资料及用户修改也不变。

下一轮会把当前目标的基本信息（元数据），以及新核心尚未收到的对话正文交给它。原生工具、审批和执行回执仍归原持有者。以前的工具调用只作记录，不作为新命令再执行。正文不完整、非文字内容无法完整交接，或超过支持容量时，会阻止操作，不悄悄丢掉前文。

切换成功后，才在同一份应用历史里写一处分界。还在执行、等待审批或结果不明时，不能切换。新连接准备失败，就保留原核心、历史和草稿。保存结果不确定时，沿原操作编号核对。原生审批和失败处理仍由所选 Agent 决定，共用协调器不表示所有工具和恢复方式都能互换。

一种支持的管理做法是：先列配置，找到准确对象，带编号和当前版本改名，再读回保存结果。两个核心使用同一套有限管理 MCP，不能任意修改配置。

**DSH 专员共享记忆选择尚未接通**。普通 DSH 下一轮选择只读记忆，是另一条已有接入方式。Hermes 留作以后的专员选项，目前不是第三种核心。换核心会保留应用正文和原生身份，但不保证模型、工具能力完全一样，也不承诺重启后恢复。

## 可以怎样吩咐

接口目录列出支持的操作。能否执行，还要看所选核心、工具是否连接、目标是否准确，以及原生权限是否允许。

| 示例 | 当前范围 |
| --- | --- |
| “把界面改成深色。” | 使用共用的应用设置，按版本保存 |
| “把回答显示为原始文字。” | 可读目录中的低频显示设置，不修改保存的正文 |
| “新建一份叫‘项目工作’的配置。” | 使用已有 AI 配置创建、编辑接口，也能从现有配置开始新建。目录里的候选项和保存参数，仍需在原生环境核对 |
| “只改这段对话的下轮配置。” | Codex／Pi／Hermes 可保存下轮配置。Claude 可选模型，强度沿用原生设置。DSH 局部模型写入口仍留空 |
| “下一轮用项目记忆，保持只读。” | 五种原生接入方式都可为下轮选只读记忆，不清除会话已有上文 |
| “找到‘项目讨论’，先不发送。” | 核对准确的对话／历史和来源身份 |
| “把这份整理文档放进已有的‘工作’分组。” | 在支持的根目录内，为 Markdown／引用分组。已有文件换组时，名字和正文不变 |
| “核对并更新。” | 手动程序事实 → 无工具 AI 分析 → 保存报告，不会自动扫描或修复整台电脑 |
| “交给已有 Codex 对话，再取回它的回答。” | 按原目标和原请求编号交办，只使用支持的原生操作 |

记忆配置参数、编辑文档记忆、检查连接、实际检索和保存，是不同操作。保存了配置，或连接正常，都不能说明已经读写记忆正文。检查连接也不需要读取私人记忆全文。

## 手动状态报告

需要新报告时，在专员指南旁点击**核对并更新**。它不定时巡检，以下三步分开进行：

| 步骤 | 做什么 | 证据范围 |
| --- | --- | --- |
| 程序事实 | 读取保存的 AI 配置、原生模型目录，以及专员工具和明确选中记忆的连接基本信息（元数据） | 每项保留来源、观察／读取时间、身份和证据摘要。没选记忆就标为未纳入，读不到的仍标未核实。 |
| AI 分析 | 只把这四项固定下来的事实交给可用的无工具文字连接，生成有固定格式的判断和简短解释 | 每项必须引用原证据编号和摘要。不能把未知改为已核实，也不能把未启用直接当作故障。 |
| 保存报告 | 检查答复，在限定范围内再查一次元数据，将事实、判断、说明和分析来源保存在本机 | 依据变了就标为不再适用。依据未核实或已变化时，报告标为部分更新，分析失败则标未完成。不改配置、不创建目标聊天、不执行工具、不召回私人记忆，也不发测试任务。 |

所选 **Codex／DSH 管理核心**与状态分析分开。状态分析仍用应用**已有的 Claude 配置文字适配器**。工具连接这一项只查看 Codex 一侧的专员连接，不能完整检查 DSH 工具是否正常。每份报告只做一次分析，分析连接关闭工具和原生对话持久化，只接收给定的元数据。它沿用该通路实际配置的提供商／模型，不能据此认为底层一定是 Anthropic 或某个型号。报告分别记录请求型号和连接报告型号。连接不能用或分析失败时，程序事实仍保留，说明标为未完成，不自动换路或重试。分析可能调用该连接配置的在线服务，报告标签和生成说明目前仍主要使用中文。

刷新或重新打开面板，会按原检查编号读取已保存的报告。简单比较身份和版本后，可以把旧判断标为依据已变化。普通读取不会重做工具／记忆 RPC 检查，也不再次调用模型。浏览器恢复时保留待核实的检查，不另建第二份。服务换代后，未完成的检查仍标待核实，不自动补发。报告只说明某个时间观察到了什么，并保留来源，不能保证账号、模型、工具或服务一直可用。

## 一次修改怎样限定范围

1. 找准对象，读取当前支持值和版本。
2. 复用合适配置。只改一段聊天时，必要时为它建立专用配置。
3. 通过界面也在使用的业务接口，只提交支持的改动。
4. 核对结果。发生冲突就重读，结果不明就保留原请求，不换编号重发。

只改一段对话，不应修改其他对话共用的配置。下轮选择也不重写已经发送的请求与回执。

配置界面写的是**从此配置开始新建配置**，不表示复制原生会话。原来的**设为新对话默认**动作已经去掉，需要时在输入框选择保存配置。原有选择和记录继续保留。

## Codex 草稿与本对话细调

Codex 可以单独调整**一段已有对话**或**未发送的新对话草稿**的模型与强度，人工入口和专员使用同一套保存规则。反复调整只更新同一份内部设置，不会不断增加命名配置，也不改全局默认。重新选择命名配置，就退出局部调整。其他 Agent 仍可选择保存配置，本版没有接通它们的局部细调。

新对话草稿只把编号和配置元数据交给专员，不带未发送的正文或文件。建议要由**原浏览器页面**按预期版本实际保存，并返回应用回执，才算完成。仅仅提交成功，不算已经应用。原文字、文件和记忆选择都保留，首次按发送才创建原生对话，并把设置归到它名下。配置已变，或已经开始发送时，旧建议不能覆盖新选择。

切页或刷新后仍保留原目标，新标签页不会悄悄接管待处理建议。需要时，要明确核对并应用。保存／应用结果不明，就沿原编号核对，不重新提建议或重复应用。细调需要已有模型目录作为依据，刷新页面不会偷偷启动 Agent 来补目录。

有些不常用的设置没有单独开关，你仍可以阅读目录，再让专员或支持的程序接口修改。紫色只说明已有这条程序操作方式，不表示这次操作已经获准。[颜色与设置设计](design.zh-CN.md)

## 交办与当前限制

五种 Agent 已有原生目标输入／结果接口。要完成一次交办，还需要兼容材料、准确目标／请求身份，以及能读取结果的方式。只有输入接口，不表示每个核心／工具组合都能走完整个流程。

Pi／Hermes 首次按原编号成功取回完整结果后，会保存符合条件的答案。服务重建后，可以按原任务编号读取。首次读取前如果断线，答案仍可能读不到。保存的结果只说明以前发生了什么，不表示执行者现在的状态。

Claude 可以在**本机操作账本**中保存有限大小的最终回答正文：只接受成功、未截断、不属于子任务的顶层 SDK final Result，最多 128 KiB，同时保存原请求身份和 SHA-256。结果匹配时，原连接关闭或重建后仍可读回，标为 `stored_sdk_result`，不表示当前还有活连接。旧回执没有正文，或结果失败、属于子任务、超限／截断、损坏、身份不符时，都不会补造成功回答。它不提供无限持久化，也不恢复完整原生会话状态。

完整最终回答必须对应原请求。“已接受”、进度片段或最近一条回复，都不能代替完成结果。缺少准确缓存或存储证据，就说明不能读取，不猜测，也不改编号补发。

原生权限仍由人处理。即使交办成功，也不等于免审批、接管桌面应用或控制所有设备。

## 仍不属于它的能力

- 代替人做登录、个人授权与原生审批决定。
- 直接接管 Codex 桌面或 WorkBuddy 的进行中工作。
- 只有界面的应用代操作，以及待接入的 AI／混合接口。
- 跨电脑调度和远程唤醒。
- 自动全局切模，或另造独立设置／执行系统。

专员可以解释哪些地方还没接入，准备支持的下一步。安装了程序、看到了工具目录，或写完了计划，都不能称为已经接通。
