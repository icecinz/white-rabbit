# 小白兔使用手册

## 小白兔是什么

小白兔把对话、资料、记忆和已经接入的 Agent 放在一个入口。你可以整理对话、选择常用配置，也可以让左上角的小白兔专员帮你设置。

Agent 是负责执行任务的原生程序，例如 Codex、Hermes、Pi、Claude Code 和 DeepSeek Harness；大模型是 Agent 调用的模型。同一个 Agent 可以使用不同模型，同一个模型也可能通过多个 Agent 接入。

小白兔优先沿用原生会话、工具、登录和审批。已经接入一个程序，不等于已经接管这个程序在所有窗口中正在做的工作；外部桌面应用的原工作连接仍在逐项补齐。

本手册随应用保存，可以在“设置”内离线阅读。专员右侧的指南是这里的高频内容摘要。查看说明不需要打开外部应用，也不会让 Agent 执行任务。

## 开始使用

1. 点“新对话”，进入首页。
2. 在输入框上方选择 AI 配置、记忆配置和接口方式。
3. 输入问题。需要资料时先添加文件、图片，或引用其他对话。
4. 发送。已经配置好的原生入口会在需要时连接；缺少原程序、登录或接入配置时，会明确提示。
5. 继续聊天，或从左侧列表回到已有对话。收到的回答保存后，刷新仍能查看。

没有合适的 AI 配置时，在“管理 → AI 配置”新建，也可以让专员帮你创建。在首页更换配置会留在首页，更新铭牌并保留草稿；按发送时才创建对话。更换配置影响下一次发送，不会重写过去的回答。

### 输入框上方的三个选项

| 选项 | 决定什么 | 怎样使用 |
| --- | --- | --- |
| AI 配置 | 哪个 Agent、模型和可支持的强度 | 选择已经保存的组合；需要修改时去 AI 配置或交给专员 |
| 记忆配置 | 本轮额外带入哪份长期记忆 | 可选“不使用长期记忆”；当前聊天上文仍会保留 |
| 接口方式 | 小白兔怎样把任务送到 Agent | 先用纯程序接口；AI 接口、混合接口未接通时会标注，不能当作已经可用 |

输入框附近的铭牌显示当前可核对的 Agent、模型和强度，例如三个名称连成一行。铭牌只显示信息，点击不会跳转。无法核对时保留“待核对”，不拿旧值补成实时状态。

### 发送与停止

Codex、Hermes 和 Pi 正在回复时，右下角始终显示停止；此时输入的下一句保留为草稿，不排队发送。回复结束后再发送。空闲且没有文字时不能发送。文件或其他材料也需按当前入口的提示完成准备。

默认 Enter 发送、Shift+Enter 换行。也可以改为 Ctrl / ⌘ + Enter 发送；中文输入法确认候选词时不会误发送。停止不代表撤销：Agent 已经完成的文件修改或外部动作不会因此恢复。

切换聊天和刷新时，这台设备当前浏览器中的未发送文字会保留。草稿不跨设备同步，也没有独立的云端草稿入口；浏览器数据被清除后不能保证找回。

## 对话与资料

### 对话列表和分组

左侧“对话”显示现有聊天。可以按来源筛选，也可以用右侧加号建立自定义分组。分组对应真实文件夹，可以在“文件夹”窗口查看位置、重新读取，或在访达中打开。

侧栏提示“原对话可能有更新”时，点“更新”重新读取原有历史。小白兔只比较来源文件的变化，不会自动重建历史索引；首次使用或无法核对时会显示“变化待核对”。Codex 正在写入时，更新会尝试读取已完成的记录，之后写入的内容需再更新；其他来源变化或文件核验未通过时，旧索引保留。

不同来源的对话保留各自身份：

- 小白兔自己保存的聊天有自己的记录。
- 已管理的原生会话继续使用对应 Agent 的原生身份。
- 只有历史索引的对话，可能尚未接上可继续工作的原生会话。

把索引放入分组时，小白兔可保存一份小引用文档用于分类；这不等于复制全部原生状态，也不会为了分组自动连接或发送消息。已有整理文档换组时沿用现有文档，不复制正文。

修改整理文档中的文字，不会自动修改 Agent 已经收到的上下文。当前还不能用修改一条路径的方式迁移全部对话保存位置；需要迁移时先让专员核对支持范围，不要直接搬走运行库。

### 添加文件和图片

“添加文件”接收的格式、大小和数量，以当前文件选择器及入口提示为准。不同 Agent 支持的材料可能不同；不能选择的格式不会因为换个按钮名称而变成可读。

文本文件会作为本轮材料准备。图片可包含原图；图片缩略图、图片说明文字和原图不是同一种输入。模型是否支持读图，还取决于所选模型和实际接入通路。

引用其他对话时，明确选择文字、文件或原图；选择并不等于已经发送。发送后可展开“本轮信息”核对实际带入的材料。资料不可用时保留原引用，不用一段猜测的摘要代替原文件。

在已打开的原生对话中，可以点“引用其他对话”，将文字和符合条件的文本文件放入当前草稿；Codex、Pi 和 Hermes 也可引用原图。已有文字和文件会保留，引用后仍需自己发送。Claude Code 和 DSH 暂不接收引用的原图。

Codex 历史中的原图按当前页面合并读取，旧索引也可使用。来源过大、变化或原文件缺失时会标明图片暂不可用；图片是否能带入下一轮仍取决于所选入口。

### 换 AI 接着聊

在 Codex 或 Hermes 对话中，从“更多 → 换 AI 接着聊”进入；选择另一位 Agent 的 AI 配置也会进入同一流程。选择要带上的已读文字、已登记文件和原图，写下接下来要做什么，预览后点“准备接续草稿”。这时不会创建对话或调用模型。

在接续草稿里核对 AI 配置与记忆配置，点发送才另开一段原生对话。文件使用所选完整版本，图片使用所选原图；没有勾选的内容不会自动补入。原生工具状态、审批和长期记忆不会随文字引用迁移，所选长期记忆另按记忆配置处理。

准备中的文字与选择仅保存在当前浏览器；切页或刷新后可从原对话的同一入口继续。新对话上方的“返回原对话”可回到准确来源，原来的未发送内容保留。

创建或发送结果不明确时，小白兔保留原编号，回原目标核对，不另建一段或自动再发。连接数量达到上限时，先在会话设置断开已结束的连接；原对话和草稿仍在。本轮接续目前覆盖 Codex 与 Hermes，其他 Agent 保留既有交接方式。

### 回答、记录和成果

你的消息靠右，AI 的消息靠左。正文优先显示回答；思考过程不作为对话内容展示。工具细节收在默认折叠的“操作记录”中，需要你处理的原生确认会单独显示。

“本轮信息”收纳配置、来源、上下文和记忆处理等记录。它描述的是那一轮保存的事实；切换现在的配置，不会用新设置补写旧记录。

支持生成文件的入口可以把成果保存成独立文件，随后预览或下载。正文提到一个文件名，不等于文件已经生成；以成果条目和保存回执为准。

## AI 配置

一份 AI 配置是常用的 Agent、模型和强度组合，可以命名、编辑，也可以从已有配置开始新建。新建入口集中在“管理 → AI 配置”。

配置名称可以写“日常聊天”“写代码”“项目讨论”，不用记住完整模型编号。“从此配置开始新建配置”会带入原配置参数，保存成另一份配置；不会复制原生会话、聊天上文或记忆库。

保存的参数、原生目录中的候选、一次模型调用的成功，是三种不同的信息。目录里能看到一个名字，不代表账号一定有权限、还有额度，或底层实际模型身份已得到验证。

### 怎样看状态

- “接入检查通过”表示本机接入条件通过检查；“原生参数检查通过”表示保存参数符合目录或继承规则，都不等于实际调用成功。
- “目录待核对”“接入待核对”表示缺少足够依据，不等于模型故障。同名模型的不同 Agent 通路分别显示检查结果。
- 卡片保留关键参数和主状态；“更多”保存程序检查、原目录来源、上次观察时间和配置版本。重新读取页面不会把旧目录变成刚刚观察的结果。
- 待确认、发送结果未知、材料缺失和保存冲突仍在操作处显示。紫色表示 AI 有直接读取或操作通路，不表示状态正常。

程序事实、AI 判断和说明分别记录。手动“核对并更新”会保存独立的检查报告；模板说明仍属于程序事实，不标成 AI 评论。依据版本改变后，原判断和说明会标为待更新。

### 设置 Agent

选择一个已经接入的 Agent，再选它实际支持的模型和参数。原生会话属于固定 Agent；把 Codex 会话直接切成 Hermes 会话并继续保留同一原生身份，目前不支持。需要换 Agent 时，建立合适的对话，再明确引用所需上下文。

专员可以帮你新建、复制或修改配置。说出配置名或具体对话；同名时先核对，不让它猜目标。

### 切换大模型

先看专员指南或模型目录中当前提供的候选，再说要使用哪一个。模型与强度支持范围以对应 Agent 的实际目录为准；不是每个模型都有同一套档位。

指南在每个 Agent 下列出模型，强度只写共同档位和例外，并显示上次更新时间。“核对模型与强度”就在“切换大模型”旁，只在手动点击时读取已打开的可用连接，不创建对话。未接通或本次无法读取的部分仍需核对。目录候选不代表账号已经通过真实调用。

手动读取成功的目录会在本机保存一份指南记录；服务重启后可看到“上次目录记录（待核实）”。这份记录只供参考，不代替当前原生连接对配置的检查。

- Codex、Hermes、Pi 已有原生模型和支持的强度选择通路。Pi 的关闭思考档位会按原生格式处理；Hermes 的请求强度也可能由提供商映射。
- Claude Code 当前接入模型选择；未明确提供局部强度覆盖时，沿用原生设置。通过 CC Switch 接入的模型名可能是别名，不能只凭名称认定底层型号。
- DeepSeek Harness 可从已打开的空闲会话读取模型目录供指南参考，提供商可能联网；局部模型切换仍未接通，不能把全局修改伪装成只改这一轮。

要只改当前对话，说“这段对话下一轮”；要修改可重复选择的组合，说“修改某份 AI 配置”。Agent 忙碌、配置版本过期或模型目录不完整时，先核对，不覆盖另一入口的新值。

### 沿用原生设置是什么意思

没有明确选择覆盖参数时，原生会话沿用它自己的配置。这不等于另一段桌面对话最后选过的模型，也不能把旧文字通路读取的默认值当作原生会话的实时选择。

旧文字通路有自己的默认值解析和回退规则，工具能力也可能受限。需要固定模型与强度时，保存一份明确配置；需要核验本轮时，看本轮回执和原生报告。请求参数回显仍不等于厂商内部实际执行型号的证明。

## 记忆配置

一份记忆配置由“名称”“备注”“记忆程序”和“程序配置”组成。备注帮助整理；身份与习惯、连接和使用方式放在程序配置中。

“不使用长期记忆”表示小白兔不额外查询或写入所选长期记忆，当前对话上文仍会带入。原生 Agent 自己的记忆与工具配置另受原程序管理；这个选项不是关闭原生 Agent 所有记忆的总开关。

### 使用方式

| 方式 | 本轮行为 |
| --- | --- |
| 只读取 | 查询已有内容，不保存这一轮的新交互 |
| 读取并记住 | 对支持保存的程序，在回答完成后进入保存流程 |

并非每个记忆程序都支持两种方式。排队不代表已经保存；保存结果在本轮信息中核对。更换记忆不会清除已进入当前会话上文的内容。

### Hindsight

Hindsight 可从交互中整理事实，再按问题检索。每份小白兔配置使用独立范围；新建或复制配置不会自动导入已有聊天，也不复制原记忆内容。

身份与习惯是额外说明，不等于已经提取成事实。即使数据保存在本机，记忆整理仍可能调用你配置的外部模型。

绑定 Hermes 原有记忆的配置固定只读，沿用已明确绑定的来源；Hermes 改用其他记忆程序时，不会自动把这个旧绑定换到另一个库。

### Hermes 文档记忆

适合少量、需要直接整理的长期约定。程序配置中可编辑 `MEMORY.md` 和 `USER.md`，分别存放长期约定与用户偏好，使用 Hermes 文件记忆核心处理；不依赖嵌入模型。

小白兔独立配置有独立文档目录，不会自动导入或修改原 Hermes 的文件。当前提供只读注入和明确的手动编辑，不自动把每一轮聊天追加到文件。只读聊天模式不禁止你主动保存文档编辑。

若 Hermes 本身改用了其他记忆核心，旧文档未必仍被原 Hermes 注入；应核对它当前的原生设置。不要让多个程序同时向同一个 Hermes home 写文件。容量超限或版本冲突会拒绝保存，不静默截断或覆盖。

### Mem0

Mem0 接入口已预留，完整可用仍需要配置提取模型、嵌入模型、对应凭据及嵌入维度。聊天模型的 Key 不一定能用于嵌入服务。

当前先接只读检索；缺少配置时保留“待配置”，不自动换成另一种记忆程序。后续需要真实写入与检索验收，才能确认完整工作。凭据在本机私有配置中填写，不要贴到聊天或公开文档。

## 小白兔专员

左上角输入框用于直接交代管理任务。点击输入框、打字或发送，都不会主动把当前页面切走；点“小白兔专员”标题才打开它固定的对话历史。需要看完整回答、操作记录或处理确认时，点标题进入。明确的“请专员设置”等入口会打开相应指南，并把光标放到左上输入框，直接输入即可。

第一次输入非空文字时，指令记住当时的对象、准确编号和已知配置版本，与草稿一起保存在当前浏览器；不附聊天正文。切页、刷新或打开专员历史都不会把它改成另一段对话。需要换对象时，明确点“改为当前”；从新的设置入口进入时，已有指令会让你选择保留原对象或改为新对象。旧草稿未记录对象时保留文字，先点“设为当前”再发送。

当前可以给已有对话选择已保存的 AI 或只读记忆配置；修改命名配置会影响使用它的其他对话。已有原生Codex对话还可从“AI配置 → 更多 → 调整本对话”单独保存下一轮模型与强度。反复调整更新同一条内部设置，不增加命名配置；重新选择命名配置就退出这份局部调整。没有专员时，“更多 → 手动调整命名配置”仍可打开原有表单。

首页可从“AI配置 → 更多 → 调整新对话”保存这份草稿的Codex模型与强度，也可以在左上告诉专员。发送前不创建对话；首次发送才把设置归到原生对话。专员只接收草稿编号和配置元数据，不附未发送的正文或材料；应用成功后铭牌更新，原文字、文件和记忆选择保留。切到别处工作，专员仍只调整原草稿。其他Agent的局部参数暂未接通，不用修改全局默认代替。

页面尚未确认应用时，建议保持待处理，专员不能只凭提交成功就说已调整。来源不明的新标签不自动接手；在专员“更多 → 核对并应用建议”明确处理原建议，不重发指令。已经改过配置或开始发送时，旧建议不会覆盖新选择。

首次发送的交接未完成时，只核对原创建，不另建；修改后的新稿仍保留。“更多 → 解除这次交接”只解除首页与已知目标的关联，不删除原对话。

局部设置保存结果未知时，保留原参数和操作编号；仅手动点“重试原保存”核对同一次操作，不自动重试。保存与原生采用是两件事，实际发送仍由原Agent核对模型与强度。“沿用原生当前设置”不会把Agent还原为最初的模型或强度。

发送之后，对象属于这次任务；清空或另写草稿不会改变它。任务结束会读回原对象的设置，当前页面正是该对象时才更新控件，保持原工作不跳页。读回失败、结果未知或等待原生确认时，标题显示“需处理”；查看历史不会清掉未解决的状态。可以从“更多 → 核对设置结果”重新读取原对象，不重新发送。原生权限确认仍需按实际请求处理。

明确从某段工作进入专员时，可点“返回原页面”回去。新对话草稿没有可直接修改的聊天编号；历史索引、设置页等没有明确目标时，需说清具体对话或配置名。专员忙时新输入仅作为草稿保存，不排队发送。

专员默认回答简短。右侧指南提供常用句式和当前可核对的模型信息，它只是提示表，不是另一种聊天模式。更完整的说明在本手册中。

### 常用指令

- “把界面改成深色。”
- “刷新已接入的 Agent 和模型清单，告诉我哪些还没配置好。”
- “新建一份叫‘日常聊天’的 AI 配置，先告诉我这个 Agent 有哪些模型可选。”
- “这段对话下一轮用‘项目记忆’，保持只读。”
- “连接 Hermes 原有记忆，保持只读，先不切换当前对话。”
- “按名称找到‘项目讨论’，先不要发送任何消息。”
- “列出‘项目讨论’里已保存的文件和原图，先不要发送。”
- “把这段对话放进已经建立的‘工作’分组。”

管理清单与“管理”页面使用同一读取入口，检查本机已接入的配置和已有目录；不代表全电脑任务或模型调用权限已全部核实。

材料清单只列引用、版本和归属，不读取对话或文件正文。共同聊天包含已保存的输入和完成成果；原生对话只包含本应用已登记的输入，不扫描 Agent 工作目录，也不补造未登记的旧材料。历史索引暂不通过这个清单读取。

缺项会单独标明；清单无缺项不代表列齐了原生历史的全部材料，也不证明 Agent 已读过文件。明确交接时，沿用原 Agent、对话和文件归属，再由原有发送流程核对完整文件。未知回执不自动补录或重发。

### 核对并更新

点击后，程序读取当前 AI 配置、原生模型目录、专员工具连接和所选记忆配置四类事实，再由无工具的 Claude 文字连接分析，独立保存本次判断和说明，最后读回界面。日常 Codex 专员对话保持原样；检查详情标注分析执行来源，区分请求型号与服务报告型号。

这是手动更新，不自动巡检或修复。检查不新建目标原生会话，不调用目标模型，不更改选择，也不读取对话或记忆正文。缺少连接、目录或依据的项目保留未核实；旧目录保留原观察时间，不因刷新变成刚刚读取。工具事实只覆盖专员扩展目录；Hermes 文档记忆只核参数，跳过全文和计数。

检查不清空或发送草稿。进行中的重复点击与页面刷新不重发分析，按原检查编号读取进度和结果；分项失败不抹掉已取得的事实。配置或依据版本改变后，旧说明标为待更新，重新手动检查才产生新结论。

### 交办其他 Agent

可以明确指定已有原生目标：“把这段虚构任务交给某段 Codex 对话，再取回它这一轮的完整回答。”专员会先找准确目标，按同一请求编号取回结果；已接受、进度片段和最近一条回答不能替代完成结果。

专员向临时普通 Codex 的完整交办已做过真实验收，发送与读取的原生确认由人在页面亲自核对后点击。这不代表所有目标 Agent 的专员交办、原生工具或桌面接管都已验证。

Hermes、Pi 的任务结果在首次按原编号完整核对成功后保存，服务重启后仍可读取；标为先前已保存的结果，不代表当前连接状态。首次成功读取前若中断，旧答案仍可能无法取回。收到“尚未确认”时，保留原编号只读核对，不能换成最新回答，也不能先假定没发出而重发。

## Agent 会话

在对话列表选择对应原生会话后，可以继续原有聊天；需要连接维护时到“设置 → Agent 会话”。不同原生程序的动作不同，只使用界面明确提供的项目。

原生工具、权限与审批仍由原程序负责。出现确认时，核对目标、动作和材料后再决定；小白兔不会因为另一次同意就自动代答新的原生审批。

在本机网页查看 Codex 来源或已绑定的普通 Codex 对话时，可从“更多 → 在 Codex 打开原对话”尝试跳转。部分原会话不能直接恢复时，核对窗口也会提供这个入口。能否打开取决于浏览器和 Codex；未打开时可在 Codex 中查找这段对话。链接使用原生对话编号，只导航，不发送或另起 CLI 会话，也不转移执行控制。它打开的是当前浏览设备的应用，因此手机和 IM.codes 预览不显示这个入口。

“断开”不等于证明所有后台工具已经退出。停止、断开和归档也不是撤销文件修改。连接变化或结果未知时保留原记录，不自动新开会话替代。

### 查看当前工作

“管理 → Agent → 小白兔已连接的工作”显示小白兔已经持有连接的工作，点条目回到同一对话，不创建副本或自动发消息。列表仅在页面可见时轻量更新；失败、连接变化或证据不足时显示未知。同一 Agent 的一个连接未知时，其他已核实的工作仍会显示。

Pi、Hermes 的结束状态会随原生事件核对，不需要打开对话来推动收尾。暂时无法核明时保留待核对；这不额外调用模型，也不代表后台工具已全部退出。

运行中也可能是在确认结果；空闲只表示小白兔已知本轮工作空闲，不证明所有后台工作都已退出。读取缓存的时间不是 Agent 事件时间。

Codex 桌面、WorkBuddy 等原应用的全部进行中任务，尚未由这个列表统一发现。没有列出不代表原应用没有工作。

### HAPI 外部工作

已经使用本机 HAPI Hub 时，可以把它报告的会话列在“管理 → Agent”的当前工作区域。小白兔自己的连接与 HAPI 报告分开显示；只有手动点“刷新检测”，或明确让专员刷新外部工作时，才会向 Hub 查询。普通页面轮询只读取小白兔已有连接的状态，不反复访问 HAPI。

首次连接使用随包的小工具，不增加一套登录页面。先让 HAPI Hub 在这台电脑正常运行，再使用小白兔当前的 Python（3.11 以上）执行，例如：

```sh
python3.12 "$HOME/.imcodes/one-ai/app/工具/hapi_work_connect.py" --origin http://127.0.0.1:3006
```

地址改为实际 Hub 的地址，目前只接受 `http://127.0.0.1:端口`。工具会在终端不回显地询问原 HAPI access token（`CLI_API_TOKEN`），沿用它原来的 namespace，向 HAPI 的认证接口交换一次 JWT。不要把密钥作为命令行参数、贴进聊天或写进手册。工具不启动 Hub、Runner、Agent，也不读取原 HAPI 配置或聊天文件。

JWT 和连接只留在小白兔后台内存。小白兔服务重启后需要重新连接；认证过期或失败时也由你手动重新连接，不自动续期或重试。清除连接使用同一个工具的 `--clear`，只清小白兔中的绑定，原 HAPI 工作保留。

列表中的“Hub 活跃”“Hub 思考中”“Hub 等待确认”“Hub 非活跃”均是 Hub 报告，不等于小白兔已验证原生执行者当前状态。查询时间不是原生事件时间。查询失败会清掉旧列表并显示待核对，不能继续把旧状态当成当前状态。

点击条目打开 HAPI 原会话页，不会创建小白兔副本、连接另一段原生聊天或自动发消息。HAPI 网页仍使用自己的登录；链接不携带密钥。目前链接指向电脑本机，不保证手机能直接打开。这个接入口只发现工作，不提供发送、审批或停止。

## 接入 Agent

先让原程序在这台电脑独立工作，再把它接到小白兔；不要为了接入另建一套模型账号或覆盖已有配置。

1. 确认要接的是原生程序、CLI 或公开协议，而不只是同名模型。
2. 完成原程序安装、登录或 API 配置，在原程序中确认能正常使用。
3. 告诉专员程序名称、安装位置和配置方式；不确定就先只读核对，不把密钥贴到聊天。
4. 核对小白兔已有接入器是否支持该版本。新增安装、模型调用和原生权限确认按实际范围处理。
5. 接入配置准备好后，在 AI 配置中选择它；需要运行时由已有入口连接。

Codex、Hermes、Pi、Claude Code 和 DeepSeek Harness 的接入程度不同。Claude Code 通过 CC Switch 使用的提供商也应沿现有配置核对，不把别名当真实型号。图形界面的 WorkBuddy 等程序，不会因为装了同名 CLI 就自动接上桌面中的原工作。

没有公开接口或原工作身份不能核实时，先留空。AI 手动操作原应用是另一种通路，不能假装成已经完成的原生会话接入。

## 接入大模型

模型通过具体 Agent 的提供商配置接入，不是把模型名字填进小白兔就自动可用。

1. 先选接入它的 Agent 和提供商，确认该原程序支持相应接口。
2. 在原程序、CC Switch 或受支持的本机配置中完成 API 地址、模型名及凭据设置；只在可信的本机入口填写 Key。
3. 让专员核对已经接入的目录和来源，再保存一份有明确名称的 AI 配置。
4. 如果需要真实调用验收，单独核对这一轮范围；只读发现不能替代调用成功。

API 配置、模型调用和嵌入服务是不同事项。余额、区域、限额、别名映射和提供商支持都可能影响结果。同名候选出现在多个 Agent 下，也不代表它们实际调用的是同一底层模型。

不要把 API Key、绑定链接或登录令牌放进对话、手册、截图和公开仓库。小白兔的设备绑定 Key 也不是模型提供商的 API Key。

## 设备

### 手机入口

可以通过已经配置好的 IM.codes 入口访问这台在线电脑的小白兔页面。手机只是入口，原生 Agent 和聊天库仍在当前服务所在电脑工作。

已使用本地网页预览时，端口通常是 `17860`、路径 `/`，以这台电脑实际入口为准。电脑需在线，所用账号和设备绑定也需可用。

手机和电脑查看同一服务的已发送对话；未发送草稿只保留在各自浏览器。电脑休眠、网络中断、预览失效或原生连接断开时，不能把页面仍可打开当作后台已经处理完成。

多电脑自动接力、远程唤醒及所有手机硬件控制仍是后续范围，不属于当前入口的保证。

## 数据保存

本机安装的运行和数据目录通常是 `~/.imcodes/one-ai/`，原生 Agent 自己的记录仍在它各自的位置。界面“文件夹”显示的是当前对话整理目录；不要把这几个位置当成同一个文件夹。

- 对话、配置、选择、回执和索引有各自的本机记录。
- 整理文件夹中的 Markdown 可能是正文文档，也可能是原生索引引用；不是所有记录都变成独立 Markdown 聊天。
- 文件、原图和成果有自己的保存与关联，不能只复制一份文字文件就认为附件也备份了。
- 把数据放在本机，不代表模型处理一定在本机。发给在线模型、记忆服务或其他程序的内容按对应服务的实际连接处理。

需要备份或迁移时，先停止新发送，让专员核对完整范围和运行状态，再复制相关数据。应用代码的更新快照不等于聊天、附件与原生 Agent 数据的完整备份。当前没有把所有设备、所有 Agent 的目录双向同步成一个云盘。

## 遇到问题

| 现象 | 先怎么做 |
| --- | --- |
| 看不到某个模型或强度 | 手动点指南的“核对并更新”；未连接时明确指定要核对的已有目标，不让它随意新建聊天 |
| 目录显示候选，但发送失败 | 看原程序登录、提供商权限、额度及本轮错误；候选列表不证明这次调用一定成功 |
| 显示“尚未确认” | 保留原请求，只读核对原编号；不要换编号重发，也不要假定尚未发送 |
| 出现原生审批 | 点专员标题或对应原生对话查看准确请求，确认目标与动作后由人决定 |
| 结果已接受，却没有完整回答 | 等待同一轮的完成证据；进度、工具片段和最近消息不是最终答案 |
| 连接变化后取不回结果 | 停止重发，保留原身份和回执；某些 Agent 的结果只在原连接缓存可用 |
| 配置或设置版本冲突 | 重新读取并核对自己的修改，不自动覆盖另一入口的新值 |
| 换了记忆仍提到旧内容 | 当前会话上文可能已有该内容；更换记忆不会抹除过去的上下文 |
| 添加图片后没有读出内容 | 核对原图是否带入、入口和模型是否支持读图；不要只看模型名字 |
| 当前工作列表显示未知 | 表示缺少可靠状态证据，不等于没在运行；先保留，不强断连接 |
| 更新应用被忙碌状态拦住 | 先核对正在做的工作和原生状态；不要强行停服务或删回执来绕过维护门 |
| 手机内容没更新 | 核对电脑在线、网络、预览端口和路径，再重新打开页面；不重复发送未知任务 |
| 内置手册打不开 | 重新打开或更新应用资源；内置手册不依赖项目文档发布。不要用任意路径文档替代缺失的随包资源 |

需要反馈问题时，给出页面、Agent 名称、现象和时间即可。无需附上密钥、私人聊天全文或完整运行日志。
